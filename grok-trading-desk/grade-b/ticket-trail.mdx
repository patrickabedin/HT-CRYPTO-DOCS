<Warning>

The empty Bitget **Trailing TP/SL** form is a create form, not proof the plan is missing \u2014 look at the live `moving_plan` row on the position.

## Two layers

| Layer | When it is placed | When it starts | How it exits |
| --- | --- | --- | --- |
| Script `TICKET_TRAIL` | Always watching | Peak uPnL \u2265 **$50** | Mark \u2264 peak \u00d7 **0.75** (give back 25% of the peak $) |
| Bitget `moving_plan` | **At entry, with SL/TP** | Mark hits **+$50** on $1000 notional (entry \u00d7 1.05 long / 0.95 short) | **2.5%** price callback (~$25 on $1000) |

Card STOP / TP1 / MAX_HOLD (2h) / STALL (30m) / R-giveback still win if they fire first. `TICKET_TRAIL` does **not** arm the Grade B whole-book $150 lock. Attached paper waits for the Bitget close (`PAPER_ONLY_EXITS` includes `TICKET_TRAIL`).

What-if (no day sit, no $150 lock) uses the same per-ticket exits, including `TICKET_TRAIL`.

<Warning>
  Do not trail 5% / 10% from entry. That can go red. The +$50 is the **arm**, not the callback. After arm, Bitget trails 2.5% of **price**; the script trails 25% of **peak $**.
</Warning>

## Why two layers

Patrick asked for a mechanical exchange net in case the bot bugs or the host dies. The script is the intended bank (tighter). Bitget `moving_plan` is the backup. Script 25% of peak $ is tighter than Bitget 2.5% of price, so they should not fight on a healthy host.

Demo follows **Expandables** TRIGGERED. Grade B 10-seat $150 lock / \u2212$100 day stop stays paper research.

## Bitget payload (do not invent another tab)

Place at entry via `BitgetDemo.attach_entry_trail` after protect. Backfill on the 15s timer with `ensure_mechanical_trail` if the first place missed.

| Field | Value |
| --- | --- |
| Endpoint | `POST /api/v2/mix/order/place-tpsl-order` |
| `planType` | **`moving_plan`** |
| Tab | Position **Trailing TP/SL** |
| `holdSide` | `long` / `short` |
| `rangeRate` | `2.5` (`BITGET_TRAIL_CALLBACK`) |
| `triggerPrice` | `trail_arm_price(entry, side)` = entry \u00d7 (1 \u00b1 50/1000) |
| `triggerType` | `mark_price` |

`track_plan` via `place-plan-order` is the wrong UI tab. In hedge mode it parked as `posSide=short` on a long. Do not use it for this net.

Hedge close long is `side=buy` + `tradeSide=close`. Do not \u201ccorrect\u201d that to one-way sell-to-close.

`infer_plan_hold`: `moving_plan` uses `holdSide` / `posSide`. `track_plan` leftover: sell + close = long. Empty `holdSide` is not a match.

`cancel_tpsl` must see both plan types. Smoke `--keep` lists `pending_all_plans` (`moving_plan` + `track_plan`), not `track_plan` only.

## LSK example (16 Sep 2026 what-if)

Expandables `LSKUSDT LONG TREND_CONTINUATION` `GROK-EVT-LSKUSDT-TREND_CONTINUATION-20260916-0310`. $1000 notional. Entry **0.4984**. Stop **0.37849**. TP1 **0.62326**.

| Number | What it is |
| --- | --- |
| **~$240.59** | **1R stop-risk**, not TP |
| **~$250.52** | Card **TP1** dollar |
| **+$340 / +$341** | Live mark **through** TP1 (last ~0.668). Not the TP |

Live Expandables already `EXPAND_STOP` flattened this ticket (~\u2212$64). What-if stayed `WHATIF_OPEN` because `plan_from_live` stamped `trigger_ts` from epoch-ms `entry_ts` (`1789529765256` = 03:36 UTC / 06:36 Athens) and `parse_dt` dropped that clock, so TP1 / MAX_HOLD / STALL never ran.

`parse_dt` now accepts unix ms. What-if TP1 / STOP bank **at the card level**, not the overshoot last. After the next host cycle this row should flip to **TP1 ~+$250.52**, not stay a juicy +$340 open mark.

A $50 / 25% trail would not flatten a still-making-highs tape. Floor from a $340 peak is ~$255. Card TP1 still wins first once the clock parses.

## Smoke

`scripts/ticket_trail_smoke.py` \u2014 paper SOL half + demo open/trail. `--keep` leaves the seat so Patrick can see Trailing TP/SL. Flatten **that** SOL only. Do not flatten leftover Expandables.

If SOL is already open, smoke aborts. `open_market` attaches the trail, so a later `ensure` may report `placed: False` / `has_plan: True`.

A visual smoke cannot wait for a real +$50 SOL move. The live plan is the real +$50 **trigger**, then 2.5% callback.

## Pitfalls (do not repeat)

| Do not | Why it hurt | Do this |
| --- | --- | --- |
| Place `track_plan` | Wrong tab; hedge parked short on a long | `moving_plan` + `holdSide` |
| Wait for the bot to see +$50 before placing the Bitget trail | Host die = naked winner | Place at entry with SL/TP |
| Trail 5% / 10% from entry | Can go red | +$50 is the trigger, 2.5% is the callback |
| Treat the empty Trailing TP/SL form as \u201coff\u201d | That page is a create form | Read pending `moving_plan` |
| List only `track_plan` in smoke | Report said `plans=[]` while trail was live | `pending_all_plans` |
| Arm Grade B $150 lock from ticket trail | Different product | Per-ticket only |
| Flatten leftover LSK / COPPER to clean a SOL smoke | Patrick left those seats | Flatten the smoke SOL only |
| Clear `telegram_429_backoff.json` / test-send | Flood mute | Shared guard |
