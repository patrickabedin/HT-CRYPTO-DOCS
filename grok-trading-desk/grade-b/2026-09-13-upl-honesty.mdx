## Root cause: two lasts

This was **not** SSR and **not** a dead WebSocket.

- Public Bitget USDT-FUTURES last lives in `/run/skynet-market/latest.json` (and the shared `md.sock` tape).
- Bitget **Demo Trading** has its own mark. On SOL it diverged about **1%** (example: public last `100.25` / later `100.70` vs demo mark `99.20` / `99.70`).

Fill-true (`78f5f61`) remade **both** `grade_b_open` and `bitget_open` from the public last so the two desk columns matched. Patrick then saw desk **+$11** while Bitget UI showed about **+$0.8**. Matching each other is not honesty.

`3862d5b` fix:

- `desk_snapshot.exchange_mark()` / `exchange_upl()` read Bitget `mark` / `unrealizedPL`.
- **Attached** paper (same symbol+side on demo) uses that mark and uPnL.
- **Unattached** paper still uses public WS last.
- Signed zeros stay zeros (`_f`).
- Lock tape in `grade_b_portfolio.py` marks attached paper from the Bitget mark, not public last.

If public last is still ~1% high, that number is **not** used for attached SOL.

## Realtime process vs market-data

`grok-desk-realtime` is **always-on**. After a host FF it keeps the **old** `desk_snapshot` module in memory until that unit is restarted.

- Restart `grok-desk-realtime` when snapshot / mark math changes.
- Do **not** restart `grok-market-data` to test UI marks. That unit owns the only public Bitget WS.

File mark can lag Bitget UI by one `grok-demo-trader` tick (~15s). REST `markPrice` / `unrealizedPL` is the live compare. Desk file vs REST may differ by a few cents.

## HIGH Telegram cards

`scripts/grade_b_upl_alert.py` + `telegram_html` kind `grade_b_upl`.

| Rule | Value |
| --- | --- |
| First send | open-book uPnL ≥ `$30` |
| Later send | new high ≥ last alerted **+ `$1`** |
| Day | UTC day rollover resets paper and demo |
| Persist | last alerted only after `ok=true` |
| Source | `grade_b_upl_high` through the shared 429 / budget guard |
| Books | `paper` and `demo` are separate watermarks |

Card shape (HTML, same rhythm as Hunter TAPE):

- Banner `GRADE B PAPER` or `GRADE B DEMO`
- Pin: `book high · fill-true uPnL` or `book high · Bitget demo mark`
- `HIGH +$n.n · N open`
- Advisory only / manual flatten if you want it

State file: `/var/lib/grok-desk/grade_b_upl_alert.json`. It stores **only** `paper_alerted_high`, `demo_alerted_high`, `day`, `ts`. There is **no** `$1`-step history.

Do not test-send. Next paper send after 13 Sep needs **≥ +$37** if `paper_alerted_high` is still `36.0143` and the UTC day has not rolled.

## Fill-true lock vs prefill tape

- Capacity is **10** open seats (`MAX_OPEN = 10` in `grade_b_portfolio.py`). The 10 Sep five-slot rollout is historical. Do not put five-slot performance claims on the current book.
- Lock arm: `GRADE_B_BOOK_LOCK_USDT` default **150**. Giveback: `GRADE_B_BOOK_LOCK_GIVEBACK` default **0.25** of the **fill-true UTC-day peak**.
- `book_high_usdt` can still show the prefill last-chase high for display (`prefill_high_usdt`).
- `fill_true_high_usdt` / `book_peak_usdt` is what the lock trails. `clear_prefill_lock()` keeps the display high and resets the lock peak to 0.
- Per-ticket exits (SL / TP1 / 2h / stall / 1R then 50% giveback) stay in `exit_reason`. The book lock flattens the **whole open book**.

## SOL attach smoke — do it once, correctly

Script: `scripts/grade_b_flatten_smoke.py --symbol SOLUSDT --side LONG`.

It writes a frozen CF plan (score 52, `FUNDING_DISLOCATION`) and asks demo ingest for `$50` @ 20x, size ~10. **It does not flatten.** No Telegram.

### Mistake 1 — smoked during flatten pause

Patrick flattened on purpose. Pause lives at `/var/lib/grok-desk/grade_b_portfolio.pause.json` (`until` + `cutoff`), **not** `/var/lib/skynet-market/pause.json`.

13 Sep: `until` 14:41:39Z, `cutoff` 14:26:39Z (15 minutes). `entries_paused()` made `consider_take` return `flatten_cooldown` **without** `_note_skip`.

First smoke (`…SMOKE-20260913-143045`) created **paper only** (`placed: 0`). Fill was stamped from public last-chase (~`100.467`) while the card entry was ~`99.486`.

### Fix — kill that paper only

Flatten **that** candidate with `flatten_open_plans([that_row])` + `write_grade_b_open_cache`. Do **not** pass `--also-demo`. Do **not** flatten the book.

### Mistake 2 avoided — second smoke after pause

After `until`, same script, no flatten:

- cid `GROK-EVT-SOLUSDT-FUNDING_DISLOCATION-SMOKE-20260913-144206`
- Card entry `99.675`, stop `98.8776`, tp1 `100.8711`
- `placed: 1`, paper open 1, Bitget SOL size 10, fill `99.688`

Live compare minutes later: Bitget REST mark `99.699` uPnL `+$0.11`; desk paper and demo `99.705` / `+$0.17`; public WS last still `100.703` (old formula would have shown about +$10). **That is the successful test.** Leave this SOL open unless Patrick asks otherwise.

Still open as of the attach: XRP leftover SHORT + this SOL LONG. `mirror_paper: true` on the demo row.

### How to attach / compare again

On the host, after `pause.until` is in the past, leave the book open:

```bash
set -a; . /etc/grok-desk/bitget-demo.env; set +a
/opt/grok-desk/venv/bin/python /opt/grok-trading-desk/scripts/grade_b_flatten_smoke.py --symbol SOLUSDT --side LONG
```

Then compare three numbers: Bitget REST `markPrice` + `unrealizedPL`, desk `monitor.grade_b_open` / `bitget_open`, public `latest.json` last. Attached rows must track the first two, not the third.

Kill one paper plan only if it has no demo attach. Never `run_flatten` for that.
