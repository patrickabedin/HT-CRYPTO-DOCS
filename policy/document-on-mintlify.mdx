Patrick's rule: **document everything crypto from now on in this repository, in the same turn as the work.**

Applies to **grok-trading-desk**, **SKYNET-SOL**, **skynet-astra**, and **any other crypto-only matter** (scalp, hunter, new books, cross-repo decisions).

The GitHub source is [`patrickabedin/ht-crypto-docs`](https://github.com/patrickabedin/ht-crypto-docs/). Mintlify publishes from `main`.

## Same-turn checklist

<Steps>
  <Step title="Write or update the matching page here">
    New engine, book, radio lane, host unit, or binding decision gets a page (or a new section on the existing engine page). Do not bury it in an index paragraph.
  </Step>
  <Step title="Use the book map">
    Parent = desk book (Grade B, Grade A, Hunter Unique, Hunter Tape, EARLY, Scalp, USELESS, Desk ops, Advisory, Research). Child = engine or worker. Everything you do for that engine stays on its page.
  </Step>
  <Step title="Register navigation">
    Add the path (no `.mdx`) to `docs.json` under the right tab and group.
  </Step>
  <Step title="Land on main">
    Commit and push this repo's `main`. Do not leave the write as a parked PR.
  </Step>
  <Step title="Pointer only in the code repo">
    If someone would look in `docs/` of a code repo, add a **one-line** link here. Do not paste the article again. Do not add new long-form markdown under those `docs/` folders.
  </Step>
</Steps>

## Write here

- Architecture and system maps
- ADRs and policy changes
- Runbooks and how-tos
- Rollout / freeze / family notes meant to be read later
- Research findings and measurement judgments
- Cross-repo crypto decisions
- New engines, books, radio lanes, systemd units, and settle paths

## Do not write here

<AccordionGroup>
  <Accordion title="Live trade checks">
    `ENTER` / `SKIP` / `WAIT` / `HOLD` / `EXIT` are timing calls. Run `scripts/trade_check.py`, `scripts/useless_scalp.py`, or the hunter brain. Do not open a docs page for a fill.
  </Accordion>
  <Accordion title="Secrets and host internals">
    This repo is **public**. Never commit tokens, API keys, chat IDs, private ingest URLs, SSH material, host IPs, or the contents of env files. Path *names* are fine. Values are not.
  </Accordion>
  <Accordion title="Iteration control logs">
    `STATUS.md`, `TEST_EVIDENCE.md`, and QA dumps stay in the code repo as a log. If the work produced a durable conclusion, write that conclusion here and keep the log where it is.
  </Accordion>
</AccordionGroup>

## In-repo `docs/` folders

Existing markdown in the code repos is a **historical snapshot**. Do not extend those files with new long-form documentation.

Exception that stays in-repo **and** is also written here:

- SKYNET-SOL armed live-copy digest (`docs/findings/teal-rules.md`) — agents must still update that file before touching Teal / TREND live-copy paths. Also publish the same rule here so it is not only buried in the monorepo.
